## Findings, from an enterprise reviewer's view

### High

H1. **Profile data (PII) is persisted in chrome.storage.local, and the privacy policy and store disclosures say it is not.**
`src/app/useJobs.js:48` writes every finished job's `result` and `params` to `chrome.storage.local` (`dci_job_<id>`), kept indefinitely. Jobs: Bulk lookup (`BulkView.vue:87`, params include the pasted list of emails/IDs, result has the matched profiles), Compare (`CompareView.vue:47`, two people's unified and source records), Health (metadata only). Also persisted: SQL history and saved queries (`dci_history`, `dci_savedQueries`, may contain literal values such as an email in a WHERE clause), SQL tabs and Query Builder drafts in localStorage (`dci_sqlTabs`, builder drafts with filter values). `site/public/privacy.html` and `docs/store-listing.md` say "Records and query results are not stored." A reviewer who checks storage will find this first.

H2. **Two auth paths, both full-API.** The default path reads the `sid` cookie (`sessions.js`) of any logged-in org and sends it as a Bearer token (`fetchProxy.js`). The optional path is OAuth (authorization code + PKCE via `launchWebAuthFlow`, `oauth.js`). The session cookie is a full UI session of the user: whatever the user can do, the extension's service worker can do. The read-only guard (`guard.js`) is code, not a Salesforce-side control. Mitigations already in place are good (below), but a reviewer will ask for one path; the OAuth path is the one an admin can control (External Client App, scopes, IP rules, revocation, Connected App usage reports).

H3. **Feedback sends data to a non-Salesforce endpoint.** `FeedbackModal.vue:15` POSTs to `the developer's Cloudflare feedback Worker` (kept indefinitely). Payload: message, details, optional name/email, optional screenshot (can show PII on screen: it captures the page or a chosen tab via getDisplayMedia), and, when "Include technical details" is ticked: the org's My Domain host (often names the client), API version, user agent, last 20 API paths with query values removed but path IDs kept (record and profile IDs can sit in paths), and up to 5 error messages (Salesforce error text can quote values). User-initiated only, previewed before sending, but it is the main reason "Network calls only to Salesforce" is false today. 

### Medium

M1. **Host permissions broader than needed.** `*.salesforce.com`, `*.force.com`, `*.salesforce-setup.com`, `*.cloudforce.com` cover every Salesforce org, community site, help/trailhead and login domain. Actual needs:
- API calls and the `sid` cookie: `https://*.my.salesforce.com/*` (covers sandboxes `*.sandbox.my.salesforce.com`, scratch/dev variants). All Data Cloud calls go to the core API (`/services/data/vXX/ssot/...`) on that host; no `*.c360a.salesforce.com` call exists.
- `*.force.com` and `*.salesforce-setup.com`: only for `orgForUrl` (toolbar click on a Lightning/Setup tab reads that tab's cookie to pick the org). Replaceable by `activeTab` (gives the tab URL on click) plus mapping the host to its `my.salesforce.com` host, which `toApiHost` already does.
- `*.cloudforce.com`: legacy instances only; candidate for `optional_host_permissions`.
- OAuth instance hosts from the token response (`instance_url`) are on `my.salesforce.com` in practice.
Gov Cloud / China / `.mil` orgs would need their own optional patterns.

M2. **`unlimitedStorage`** is only needed because of caches and persisted job results (H1). With metadata-only, opt-in caches it fits in the default 10 MB.

M3. **Third-party hand-off to Diagramforce.** `lib/diagramforce.js` opens diagramforce.com and `postMessage`s the data model diagram (object, field and relationship names, no records, no session). Feature switch `diagramforce` is on by default (`src/features.json:9`). Schema names can be sensitive for a pharma client (custom object names reveal programs). Disclosed in the privacy policy.

M4. **Publisher identity is inconsistent.** Store listing: developer email at cloudkettle.com, privacy policy at ateko.com, "offered by" blank. Repo: privacy policy hosted at `data-cloud-inspector.mathes.dev/privacy` with no publisher name; `docs/store-listing.md` says "CloudKettle's developer account"; the feedback form shows `mathes.kanagarajan@cloudkettle.com`; sidebar/Help credit "Created by Mathes, Ateko" (in the 1.0.6 and 1.0.7 zips). A reviewer cannot tell who is accountable.

M5. **No explicit CSP, no managed policy, no published security docs.** The MV3 default (`script-src 'self'; object-src 'self'`) already blocks eval and remote scripts, so the risk is low, but reviewers look for an explicit `content_security_policy`, a `storage.managed_schema`, SECURITY.md and a reproducible build. None exist. No LICENSE, no CHANGELOG.

M6. **Supply chain.** `xlsx` comes from a tarball at `cdn.sheetjs.com` (not the npm registry), so Dependabot/npm audit don't track it. osv-scanner reports GHSA-4r6h-8v6p-xvw6 (prototype pollution, fixed in 0.19.3) and GHSA-5pgg-2g8v-p4x9 (ReDoS, fixed in 0.20.2) against 0.20.3: false positives (0.20.3 is past both fixes; the npm advisory lists no patched version because npm's `xlsx` stopped at 0.18.5), but they will appear in any client's scan; document them. No CI, Actions or branch protection yet; releases are built locally by hand.

### Low

L1. OAuth details (good overall): public client, PKCE S256, `state` checked, no client secret anywhere, **no `scope` parameter sent** (scopes come from the user's External Client App; document the minimum: `api`, and tell admins not to add `refresh_token`). Refresh tokens are never stored (only `access_token` is kept). Access token in `chrome.storage.session` (`dci_oauth_<orgId>`, gone when the browser closes, dropped on a 401). Client ID kept in storage.local (not secret). Missing: no explicit revoke call on "Log out" (token is only forgotten locally, it stays valid in Salesforce until it expires).
L2. Cookie handling (good overall): reads only cookies named `sid` on `salesforce.com`/`cloudforce.com`, re-read on every call, never stored, never sent to the app page (service worker only), sent only as `Authorization` to the org's own host with `credentials: 'omit'`. Message handler only accepts the extension's own pages (`background/index.js:38`); no content scripts, no `externally_connectable`, no `web_accessible_resources`.
L3. The read-only guard allows any GET under `/services/`, including `/services/apexrest/...`, where a custom Apex GET endpoint could have side effects. Could be narrowed to `/services/data/` (+ `oauth2/userinfo`).
L4. No eval / `new Function` / remote code in source or the shipped bundle. `innerHTML` appears only inside Vue's runtime and html-to-image; no `v-html` in source; the print/export iframe escapes HTML. jszip's bundle contains an unused `importScripts` (its worker shim); the MV3 CSP would block remote loads anyway.
L5. Logging: no `console.*` calls in `src/`; tokens are never logged.
L6. Other storage (fine, disclosed): settings, layout, visits per page (paths only), saved orgs (domain, org ID, username, optional name), feedback name/email, metadata catalog and org caches (`dci_catalog_*`, `dci_s_*`: streams, mappings, rulesets, segment names, usage, record IDs of DMOs/DLOs/CIs, up to 7 days).
L7. Repo contents for going public: no secrets in tree, history (105 commits; 91 had text diffs) or the 30 release zips. Test fixtures use fake org IDs plus one real dev org ID (in `oauth.test.js` and `storageUsage.test.js`), harmless but worth replacing. `docs/store-listing.md` names CloudKettle. No client names found.

## Why Spin.AI says "External comms: Medium"

The manifest declares no non-Salesforce host, but static scanners read the bundle. The shipped 1.0.7 zip contains: the feedback POST to the developer's Cloudflare feedback Worker (a live `fetch` with user data, H3), `window.open`/`postMessage` to `diagramforce.com` (M3), and outbound links (linkedin.com, medium.com, developer.salesforce.com, admin.salesforce.com, sheetjs.com, vuejs.org...). Combined with `cookies` + broad hosts, a scanner rates the ability to move session-derived data off-domain as Medium. Removing the feedback fetch (or making it a mailto/GitHub link) and the Diagramforce hand-off (or off by default and admin-disableable) are the two changes that move this rating. "Vulnerabilities: Medium" most likely comes from the xlsx advisories (M6).
